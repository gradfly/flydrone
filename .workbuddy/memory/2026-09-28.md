## autoplay 高度保持：用模拟手势把高度锁在 ~1 m

需求：autoplay 模式下用 `d.pos[2] > 1.15 ? DROP : FIST` 这类手势法把高度控制在 1 m 左右。

实现（`docs/live/app.js`，全部改动仅此一个文件）：
- 新增 `ALT_HOLD`（openness 0.1、**size 0** 的"静止手"）与 `ALT_CLIMB`（openness 0.95 的"张开手掌"），复用 swat 游戏的 `DROP`。
- `autoHeightGesture(alt)`：> `ALT_CEIL(1.05)` → DROP（注下垂光流="上升错觉"→大脑下降）；< `ALT_FLOOR(0.80)` → ALT_CLIMB；否则 ALT_HOLD。simTick 的 autoplay 分支由固定 neutral 手势改调此函数。
- 关键坑：**hold 手势的 size 必须为 0**。GestureIllusion 在手"消失"分支会把 prevSize 归零，若重新出现的手带 size（如 FIST 的 0.15），`growth=0.15 > loomGrowth=0.03` 会注入假 looming → 触发巨型纤维逃逸打断巡航（实测 escapes 8 vs 2，loomTicks 54）。size=0 后 loomTicks 恒为 0。
- UI：AUTO CRUISE 的 sub 行实时显示当前高度，正在纠高时 chain 显示错觉通路（`il.channel`）。

调参数据（无头 Node 直跑 Pilot + 浏览器 CDP 实测，种子 0/1/3/6）：
- 原始 neutral：高度随种子漂到 0.87–1.38 m，且种子 0 在起飞后 15 s 内只有 0.6 m。
- 用户原式（>1.15?DROP:FIST）：均值 0.99 m，但无下限，部分种子掉到 0.55 m；浏览器种子 0 前 15 s 0.58–0.66 m。
- 加下限 0.85：稳在 1.05–1.19（整体偏高 ~1.1）。
- **最终 1.05/0.80：5 s 起锁在 0.94–1.05 m（多数 0.98–1.00）**，浏览器 40 s 无 JS 错误。

工具教训：agent-browser daemon 仍会卡死（`timeout` 杀掉 open 后无输出）。可靠替代：直接 spawn 系统 Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）`--headless=new --remote-debugging-port` + SwiftShader 参数，Node 22 原生 WebSocket 连 CDP，Runtime.evaluate + Page.captureScreenshot。**下次注意**：Chrome 的 `--user-data-dir` 一定要放在 `%TEMP%` 下，**不要**放在项目 `.workbuddy/` 里——那是 OneDrive 同步目录，且删掉 ~1600 个缓存文件会触发 safe-delete 的批量删除确认（阈值 50），清理不掉。沙箱 shim 也会拦截 Node 的 `fs.rmSync`（trash 报错），所以用 `%TEMP%` 让它随系统清理最省事。

## 2026-09-28 下午 3：临近碰撞高亮加强 + 修复"卡进墙/障碍物"

### 高亮重做（models.js + room.js）
- 旧高亮是 LineSegments 边框，WebGL 无视 linewidth，永远 1px。改为 12 根 0.034m 立体霓虹管（neonFrame()）+ 一层半透明光晕外壳 halo（BoxGeometry 外扩 0.14，DoubleSide，depthWrite:false，夜间 AdditiveBlending）。
- highlightNearest(simPos, level, touching) 双驱动：looming 点亮最近柱；原始接近度（gap<0.25m 线性 ramp）点亮任何贴近的柱（可同时多根）；实际接触(touching)变红 0xff3b30，heat>0.5 变橙，其余青色。夜间把未报警柱的霓虹调暗到 0.2（否则报警的被淹没）。
- room API 新增 lit() 返回当前点亮的障碍名（headless 验证用）。

### 防卡死（engine.js，三层）
根因：旧 collide() 撞上就把位置整体回退上一帧+速度整体反向 → 两轴全锁死；且静止贴面时视野是静态图像、无 optic flow 无 expansion → looming 反射永远不触发 → 卡 20+ 秒（seed3/5 实测 59%/48% 时间卡住）。
1. collide() 改为最小平移量推挤出（MTV，3 轮迭代含墙重夹持，允许从顶上翻过 z0>=0/z1<=hz 才是候选）；返回推挤法线 n。
2. step() 只消掉射入表面的速度分量（1+bounce=0.45 恢复系数），切向速度保留 → 沿表面滑动。
3. Decoder 接触反射：tel.touching（telemetry 新增字段）以 contactCooldown=2.0s 限频触发与 looming 相同的巨纤维逃生（随机 climb/left/right），escCause 记录 'contact'|'loom'。物理修复后 seed0 出现"沿墙爬行36s"，靠这层解决。
4. app.js contactUntil 0.7s 内手保持 ALT_HOLD：接触逃生可能选 climb，高度调节器的 DROP 幻觉会抵消它。

效果（12 布局 × 90s，autoplay）：touch 14.9%→0.14%，jam 14.9%→0.00%，最长卡住 6.7s→0.00s，穿透 0；chair run 同样改善。travel 19.8m 不降。

### 配套
- engine.js 支持 `?seed=<n>` 固定障碍布局（typeof location 守卫，Node probe 不受影响）。
- record 模式 FD.state() 暴露 build/simT/alt/pos/touching/collisions/escapes/escCause/loom/lit。
- .workbuddy/hl_verify.mjs 保留：自拉 Chrome + 原生 WebSocket CDP 的无头验证 harness（soak + 截图）。
- 版本号教训：models.js/room.js 的 import 之前没带 ?v=，浏览器缓存旧文件导致 FD.lit 报错——现在全部 import 都带 ?v=7，以后改任何 live/*.js 都要 bump 全部三处。
